# Mac 邮箱手动授权

邮箱密码和 Google OAuth 令牌继续保存在系统钥匙串原来的 `com.oyenza.poni.mail` service 下，account 保持邮箱账户 ID。不迁移、不修改现有访问控制，不把密码或令牌写入应用数据目录或日志。

主应用直接使用原有 Security Framework 访问钥匙串。独立 `IslandCredentials` 组件、进程协议与对应打包步骤已撤回，应用包不再携带或启动该组件。

## 使用方式

- 启动、安装后首次运行、恢复桌面、普通刷新和后台收信只进行静默访问。已有授权可继续收信；需要系统交互时显示“待授权”，停止自动重试，不弹出系统授权框。
- 到“高级设置 → 邮件”展开对应邮箱，点击“授权”才允许本次访问显示系统授权框。授权成功后自动恢复收信；拒绝后保持待授权，可以再次手动授权。
- 编辑账户中的“保存并授权”也是用户主动发起的授权操作。缺少或失效的密码、应用专用密码或 Gmail 令牌需通过此入口更新。
- 移除账户使用静默钥匙串删除，无法访问时保留账户并说明先授权再移除，不将删除失败显示为成功。

## 交互边界

旧登录钥匙串可能忽略仅适用于数据保护钥匙串的请求级禁用 UI 参数，因此沿用现有 `security-framework` 的 `SecKeychain::disable_user_interaction` 守卫。该开关作用于进程，所有邮箱的钥匙串读、写、删除共用一把互斥锁：后台操作在禁止交互期间完成并恢复开关，手动授权在同一锁保护下执行，避免多邮箱同时操作时互相放开弹窗。网络请求不持有此锁，也不新增常驻组件、后台计时器或依赖。

普通刷新不会清除凭据暂停标志；只有手动授权或保存成功才恢复。Gmail 后台更新令牌的写入同样静默。锁屏或停用导致的取消不标记为用户拒绝，过期结果不会覆盖当前账户状态。直接系统授权对话框已经出现时，需用户完成或取消，主应用不代替用户操作。

现有编译、测试、签名与离屏预览只能证明各自覆盖范围；未新增测试或读写临时/真实凭据进行验收。实际邮箱授权、拒绝后重试和后台无弹窗需实际使用确认。
