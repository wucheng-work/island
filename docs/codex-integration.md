# Codex 消息、快捷回复与对话

Island For Mac 可接收 Codex 的本轮结束提醒、审批提醒，在岛内快捷回复，并展开查看原会话的文字对话。通过本地 MCP 工具 `island_ask`，Codex 也可以向岛发送一个普通问题，等待你输入回答。

普通会话回复通过 Codex 官方 CLI 消息队列发送到原会话；MCP 问题的回答仍只返回发起该问题的工具调用。Island 不接管会话执行。“打开 Codex”打开应用，由你选择原会话。

## 1. 在 Island 开启连接

在 Island 的“设置 → 高级设置 → Codex 提醒”中开启“启用 Codex 提醒”。只有开启时，应用才监听当前用户的本机 Unix socket；关闭开关或退出应用会关闭连接、取消等待中的问题并清除岛内的消息正文和草稿。再次开启不会恢复旧消息。

连接不使用公网端口，不需要 API Key、邮箱密码或 Codex 登录凭据。socket 位于 `~/Library/Caches/Poni/codex/bridge.sock`，专用目录权限为 `0700`，socket 权限为 `0600`。同一个 macOS 用户运行的其他进程仍属于这个本机信任范围。

岛内消息、读取的历史和草稿只驻留内存，不写入 Island 日志或数据文件；明确发送的文本会进入 Codex 自己的会话队列。锁屏时隐藏岛内预览，解锁后可继续查看。通知声音遵循 Island 的 Codex 声音设置。

## 2. 配置本轮结束和审批提醒

本应用提供 `--codex-hook` 命令，读取 Codex 官方 Hooks 的 stdin JSON。它支持 `Stop` 和 `PermissionRequest`：

- `Stop` 显示“Codex 已回复”，并预览 `last_assistant_message`。这表示当前轮次停止，不表示整个任务已经完成。
- `PermissionRequest` 只提示回 Codex 审批，不自动同意或拒绝操作，也不在岛内执行权限审批。

如果使用默认 `CODEX_HOME`，在 `~/.codex/hooks.json` 的现有 `hooks` 对象中合并以下条目；已有其他 Hooks 和 `description` 等字段须保留。路径中的空格需要保留示例中的双引号转义。

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "\"/Applications/Island For Mac.app/Contents/MacOS/poni\" --codex-hook",
            "timeout": 5
          }
        ]
      }
    ],
    "PermissionRequest": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "\"/Applications/Island For Mac.app/Contents/MacOS/poni\" --codex-hook",
            "timeout": 5
          }
        ]
      }
    ]
  }
}
```

新增或修改的非托管 Hook 需要在 Codex CLI 输入 `/hooks`，审阅并信任当前定义，未信任时不会执行。Hooks 默认启用；若曾关闭，请在 `config.toml` 已有的 `[features]` 中将 `hooks` 设为 `true`，不要重复创建同名表。重新打开 Codex 或开启新会话，使配置重新加载。Island 不会自动修改你的 Codex 配置或替你确认信任。

应用未运行、连接未开启或事件格式有误时，Hook 安静退出，退出码为 `0`，stdout 为 `{}`。它不阻断 Codex 的原有流程。不要使用不存在的 `Notification` Hook 事件名。

旧版配置中的 `notify` 也可指向这个入口，用于兼容 `agent-turn-complete` 事件：

```toml
notify = ["/Applications/Island For Mac.app/Contents/MacOS/poni", "--codex-hook"]
```

`notify` 必须位于 TOML 顶层，保留原文件其他设置。该兼容入口从 argv 读取事件；是否可用以所安装 Codex 版本的配置参考为准。同一轮结束提醒选择 Hooks 或旧版 `notify` 中的一种，避免重复提醒。

## 3. 快捷回复与展开对话

普通结束提醒带有有效会话 ID 时，右侧显示“确认”：点击直接向对应 Codex 会话发送固定文本“确认”，不打开输入框。消息列表中的“确认”执行同一操作。发送中阻止重复点击；队列接受后该条提醒显示已确认，已有自定义草稿不会清除。失败时可以明确重试；结果未知时先打开并核对原会话，不自动重发。权限审批消息没有确认按钮，仍须回 Codex 处理。

消息列表按非空会话 ID 合并成一张卡片，不按会话名称合并；没有会话 ID 的消息仍各自显示。卡片首行显示会话名、未读数量和最近收到消息的本地时间，次行显示摘要及确认操作，不再显示“已回复 · 工作目录”。有未读消息时使用主题色浅底和数字徽标，已读使用中性底色；关闭预览仍显示数量和时间，但隐藏名称与正文。

新收到的提醒默认未读。打开完整会话后，该会话的普通对话提醒标为已读；单条问题、审批或紧凑预览只清除当前展示的提醒。完整对话正在显示时，同会话普通新提醒直接视为已读，其他会话仍累计。确认成功加入队列后仅清该条未读；失败或结果未知不清。浏览列表、锁屏或熄屏不清未读。数量仅统计 Island 本机收到且仍保留的提醒，退出或关闭接入后随内存消息一同清除，不等同于 Codex 全部历史消息的未读同步。

每张卡片默认展示最新提醒，有待回答或正在返回的普通问题时优先展示该请求，未查看的审批和单条问题也保留入口。待答/审批页底部“更新提醒/更早提醒”可切换同一会话的其他提醒，原始问题、回答状态和草稿仍独立绑定对应请求。普通完整对话直接使用官方历史，不再保留重复的会话提醒导航。

点击提醒或消息卡片正文打开对话，可输入自定义回复并点击“发送”，不会因为回车确认中文候选词而发送。结果待核对时打开紧凑输入区，也可点“展开对话”查看原会话；“更早消息”继续分页，“刷新”重新读取最近内容。同一会话的自定义草稿共享，不同会话互相隔离。顶部接入状态灯成功时使用绿色，未启用灰色，启动失败红色，与主题色分离。

此功能需要所安装的 Codex CLI 支持 `queue` 和 `thread/items/list`。Island 按需启动短时读取进程，只调用初始化与读取接口，不恢复或启动另一份会话执行器；没有用于历史读取的常驻进程或定时轮询。打开对话和收到该会话的新结束提醒时读取历史，后者仅在完整对话页展开时执行。附件、工具输出和推理不作为聊天气泡显示；长正文最多显示前 16000 字。

岛上Codex提醒采用内容优先排版：11pt淡灰常规字展示会话标题，13pt亮色正文摘要最多展示两行，提醒为500×68pt。摘要跳过独立Markdown图片行与代码围栏行、去掉行首标题/引用/列表符号，合并空白后最多保留160字；完整消息仍可点击查看。Classic与Pill共用同一文字布局，确认按钮及隐私预览开关保持原有行为。

提醒、消息列表和对话顶部优先显示 Codex 的真实会话名称。提醒到达时通过 `thread/read` 只读取名称，不加载完整历史；打开或刷新对话时也会更新名称。名称按会话 ID 缓存在内存中，不用项目文件夹名冒充名称；确认尚未命名时显示“未命名会话”，读取前或失败时显示“Codex 会话”。Codex 项目目录的内部 ID 不作为项目名称显示。关闭消息预览时提醒和列表不显示会话名称。对话标题单独占一行，长名称省略显示，不与操作按钮重叠。

对话采用左右气泡：Codex 在左侧使用淡灰背景，你的消息在右侧使用淡主题色背景。列表的接入配置、清空操作留在消息列表；进入对话后顶部只保留返回、会话名以及打开/刷新会话操作，不再重复显示工作目录。历史消息与进度显示使用紧凑辅助行。进度文字默认折叠，可点“显示进度”查看；这只改变岛内展示，不删除原历史。输入区正常状态不保留固定说明空白，仅在发送、错误或结果待核对时显示提示。发送操作位于底部输入区，需明确点击。

历史中的用户文本若为完整的 `send_user_message_question_reply` 系统回执，岛内只显示 `answer`：单条直接显示回答，多条按顺序编号分行。协议标签、`questionItemId` 和重复问题不进入气泡；空回答有明确占位，空回执或格式无法识别时显示说明并提示到 Codex 查看。转换在显示长度截断前进行，仅影响岛内用户消息展示，不修改原会话、普通文字、助手消息或发送内容。

“已加入 Codex 队列”仅表示 Codex 接受了排队请求，不代表模型已经处理。已加载会话可继续消费消息；闲置会话未继续时，请在 Codex 中打开原会话。Island 不自动启动 daemon 或其他执行器。发送与读取均限时 15 秒；无法确认投递时保留草稿，不自动重发。请先核对原会话，确定未收到后再点“已核对，未收到”，然后明确点击发送。

会话历史只显示 Codex 返回的真实消息，不把排队请求预先插成用户气泡，避免收到正式历史后重复显示。读取失败不清除已有对话或草稿。关闭 Codex 接入会清除岛内历史和草稿，但已交给 Codex 的排队消息不会因此撤回。权限审批始终回到 Codex 处理。

## 4. 配置岛内提问和回答

在 `~/.codex/config.toml` 中添加独立 MCP 服务；如果已使用其他 `CODEX_HOME`，在对应目录内配置。不要覆盖原有设置或其他 MCP 服务。

```toml
[mcp_servers.island]
command = "/Applications/Island For Mac.app/Contents/MacOS/poni"
args = ["--codex-mcp"]
startup_timeout_sec = 10
tool_timeout_sec = 660
```

这里的 `command` 是直接执行的文件路径，保留空格即可，不要再在路径内容中加入 shell 引号。每个 MCP 请求是 stdin/stdout 上的一行 JSON；辅助进程不会打开第二个 Island 窗口。

保存配置后重启 Codex 或开启新会话，确认 MCP 工具列表中出现：

| 工具 | 用途 |
| --- | --- |
| `island_notify` | 把需要关注的结果摘要交给 Island，不等待回答。 |
| `island_ask` | 向 Island 发送一个普通问题，等待用户明确发送文本。 |

添加服务不意味着 Codex 会自动在每一轮调用这些工具。可以在当前会话明确要求：

```text
需要我回答普通澄清问题时，请调用 island_ask，并把问题完整写入 text。不要用它处理权限审批、密码或专用确认流程；取消或超时不表示同意。
```

两种工具都要求 `title` 和 `text`，可选 `thread_id`、`turn_id`、`cwd`。会话和轮次 ID 只在已知时提供，不要猜测；未提供会话 ID 时，辅助进程会尝试使用 `CODEX_THREAD_ID`。缺少会话 ID 不影响当前工具调用接收自己的回答。

```json
{
  "title": "确认导出格式",
  "text": "导出结果需要 PDF 还是 Markdown？",
  "cwd": "/Users/example/Projects/demo"
}
```

标题最多 120 字，问题或摘要最多 16000 字，回答最多 2000 字。请求受 96 KiB 的单条传输大小限制；Island 同时最多处理 8 条本地连接，单个 MCP 辅助进程最多接受 16 个未结束的工具调用。

## 5. 回答、取消与断线

Codex 消息列表右上角的“清空已结束”可清理通知、已回答、已取消或已过期记录；等待回答、正在发送、投递结果未知以及仍有会话草稿的入口会保留。这只清理 Island 的本机消息列表，不会删除 Codex 原聊天或撤回已经排队的文本。没有可清理记录时不显示该按钮。

`island_ask` 最长等待 600 秒，所以 MCP 配置将 `tool_timeout_sec` 设为 `660`，留出连接和返回时间。在 Island 的 Codex 页选中对应问题，输入文本后明确发送。草稿与该请求绑定，不会发送到其他会话。

岛内发送后先进入发送状态；桥接成功写回原工具连接后才显示已回复。这证明文本已经返回连接，不等于 Codex 已完成后续处理或对方已读。

取消、超时、Codex 关闭工具连接、关闭 Island 连接开关或退出应用，都会结束等待。取消和超时以工具错误结果返回，不隐式同意任何操作。连接断开后旧问题不能继续发送；原会话可重新发起问题。普通超时或断线保留岛内草稿便于复制；关闭连接开关会清理草稿。

MCP 服务未连接 Island 时会返回明确错误，不会伪造“已发送”。原 Codex 会话的后续行为由 Codex 决定。审批提醒必须回 Codex 处理；Island 不代替审批、密码输入或其他专用确认。

## 6. 排查连接

1. 确认应用安装路径与配置一致，并在 Island 设置中开启连接。
2. Hooks 没有提醒时，核对 Codex 中的 Hook 信任状态和事件名。一次未提醒不代表任务或审批已通过。
3. 工具列表没有 Island 时，核对 TOML 中的 `[mcp_servers.island]`，并重启 Codex 或开启新会话。
4. 问题十分钟后失效时，在原会话重新调用 `island_ask`；不要把旧草稿视为已发送。

仅隔离验收时可以设置 `PONI_HOME`。Island 与 Hook/MCP 辅助进程必须使用相同的 `PONI_HOME`；此时 socket 位于 `$PONI_HOME/cache/codex/bridge.sock`。日常使用无需设置该变量。
